# astroffers

PWA listing the NGC 2000 objects visible on a given night at a given location. Vite, React 19, TypeScript (strict), MUI 9 (dark, emotion), Highcharts 13, sass; deployed as a Render static site ([render.yaml](render.yaml)) — **every push to `master` deploys** to https://astroffers.hasyee.com. Successor of the archived `hasyee/astroffers-electron` (desktop) and `hasyee/astroffers-app` (React Native) apps; tooling and the shared modules (`provider/`, `moon/`, `debounce/`, `version/version.hooks.ts`) follow the sibling `../astro-calendar` repo (MUI as well) — keep them in sync when fixing one. `location/` started from it but differs here (the coordinates are in the query).

## Structure

- Per-domain directories, flat file names: `src/<domain>/<domain>.<role>.ts(x)` (`.hooks.ts`, `.provider.tsx`, `.utils.ts`, `.types.ts`, `.scss`).
- State: the shareable state of the main view is in the URL query (`RouterProvider isQuerySticky`): `date=YYYY-MM-DD`, `lng`, `lat`, `sort` and the filter (`alt`, `bf`, `mag`, `sb`, `tw`, `ot`, `ml`; `const` / `exConst` and `types` / `exTypes` list the selected or, when more are selected, the excluded keys, and are left out when everything is selected). Each domain has its codec in its utils (`...FromQuery(query, fallback)` / `...ToQuery`).
  - `query/`: `initQuery` (before the first render) completes the query from `localStorage` / the defaults. `/calendar`, `/help` and `/about` have no state in their query: `QuerySync` removes it there and restores it on the way back from `StoredState`, which mirrors the query while it holds the state (the date only in memory — the night of today on every start —, the filter and the order also in `localStorage`; the place with its name is stored in `location/`, the name only there).
  - The hooks read through `useStatePart` (from the query when it holds the state, else from `StoredState`; selected serialized, so values keep their identity and nothing is recalculated when the state moves) and write through `useStatePartSetter` (`useQuerySetter`: `replaceState`, no history entry; or `StoredState`).
  - The query is sticky: navigating without a query keeps it and back / forward change the path only, so closing a drawer or a dialog by the history never reverts a change made in it.
  - The rest are small `StateProvider`s on the hand-rolled context selector (`provider/context.selector.ts`, `useSyncExternalStore`): the stored state and place, the list search and the result.
- Routing: `router/` is tinc's router without its breadcrumb (`RouterLocation` / `usePathname` instead of `Location` / `useLocation`, not to clash with `location/`; added: `useNavigate({ replace })`, `useGoBack`, `useMatchPath`, the sticky query and `useQuerySelector` / `useQueryParams` / `useQuerySetter`; `Routes`, `Route`, `Link` are there but unused). `/calendar`, `/help`, `/about` and `/object/:ngc` open dialogs over the main view: they stay mounted and read `useMatchPath` (not `Routes`), so their closing is animated. Closing calls `useGoBack` (history back when opened in the app, else replace with `/`); stepping between objects replaces the route. `render.yaml` rewrites every path to `index.html`, the service worker's navigate fallback does the same offline.
- `result.hooks.ts` `useCalculation` reruns the calculation in a web worker (`calculator.worker.ts`) 300 ms after any input change; responses are matched by `jobId`.
- The calendar (`calendar/`, opened from the header) is ported from astro-calendar: a full-screen `Dialog` mounted only while open, with its month in the query (`month=YYYY-MM`, the month of the chosen night by default, removed after the closing animation of the calendar), swiped like the details (previous/current/next month), and its own worker (`calculator.calendar.worker.ts`, month by month, cached in `useCalendarMonths` per location and twilight; `calculator.bands.ts` from astro-calendar, but with the filter's twilight instead of a fixed -18°). The day popover reuses the summary's `NightTable`; "Show objects" sets the date and closes the calendar.
- `calculator/` is the strict-ESM port of `astroffers-core`, reusing astro-calendar's sun/moon/night modules; it was checked against the original core (identical results except Moon rise/set, a few minutes off since `suncalc` 2 is more accurate).
- `catalog/catalog.json` is generated by `scripts/catalog.mjs` from astroffers-core's `data/` (radians, arc minutes, missing values omitted; 4 MB → 1 MB). The core repo is archived and no longer checked out next to this one — pass its path as an argument.
- Responsive at 960px (`media/media.hooks.ts`): wide = Electron-like filter panel (open by default, the menu button of the header closes it) + table, narrow = React Native-like filter drawer, cards and a full-screen details carousel (`swipe/swipe.hooks.ts`, also used by the calendar: previous/current/next pages side by side, the track is reset in a layout effect after the step, so no blank page shows between them).

## UI conventions

- Theme in `theme/theme.ts` (dark, flat `#1c2127` papers without the elevation overlay, 14px base font, small fields by default) with `cssVariables: true`: the stylesheets use `var(--mui-palette-*)`, the charts read the palette through `chart/chart.colors.ts`. `StyledEngineProvider injectFirst` (`index.tsx`) puts MUI's styles first, so the SCSS overrides them at the same specificity. Styling stays in the per-domain `.scss` files, not `sx`.
- Import components and icons by path (`@mui/material/Button`, `@mui/icons-material/Close`); icon names are not guessable (the outlined help circle is `HelpOutlineOutlined`, `HelpOutline` doesn't exist), check `node_modules/@mui/icons-material`.
- Text buttons and `IconButton`s everywhere; fields are outlined `TextField`s with floating labels. Choices made in a dialog (Location, Object types, Constellations) are read-only `SelectorField`s (`input/input.selector.tsx`). Dialogs use `DialogTitleWithClose` (`dialog/`), placeholders `EmptyState` (`empty/`).
- Preview images (CDS hips2fits, DSS2) are grayscale via CSS; clicking the details preview opens a 1200px color version in a new tab.
- Search: `*` in the Messier or name search matches every object having one; on phones the Messier field uses `inputMode="tel"` (a numeric keypad that has `*`).

## Gotchas

- A selector of `useStateSelector` / `useQuerySelector` must return a primitive or an otherwise stable value: a new object on every call makes `useSyncExternalStore` loop. Select a string and parse it in a `useMemo` (`useQueryParams`, `useStatePart`).
- Swipes (`swipe/swipe.hooks.ts`) call `preventDefault()` on the `touchmove`s of a horizontal swipe (non-passive listener): otherwise Chrome on Android starts a fling with nothing to scroll, and the next tap anywhere only stops it instead of clicking. Happens on a real device only, not in the emulator or headless.
- A `useEffect` callback must not return `element.scrollTo(...)`: it returns a Promise in current Chrome, React calls it as the cleanup, and the whole root unmounts. Use a block body.
- Highcharts polar: `pane.background: []` crashes (`innerRadius` of undefined) — pass an object; axis labels at the sides get ellipsized to nothing without a fixed `chart.margin` and `textOverflow: 'none'`; round `this.value` in label formatters (float ticks like 89.999). Highcharts 13 rounds the elements of a pane (`pane.borderRadius: 3`, e.g. the plot bands of the clock face): turned off in `chart.theme.ts`.
- `DialogTitle` + `DialogContent` zeroes the content's top padding, which clips the floating label of a first field — give that `DialogContent` a top padding (see `location.scss`). The `Autocomplete` of the place search ignores every `onInputChange` but typing (it resets the input itself on selecting) and uses `clearOnBlur={false}`.
- iOS zooms into inputs below 16px: `index.scss` sets 1rem only under `@supports (-webkit-touch-callout: none)` (iOS only; `!important` beats MUI's more specific selectors). The mobile tap highlight is turned off globally.
- hips2fits sends no cache headers: the service worker caches it (`runtimeCaching` CacheFirst in `vite.config.ts`), and the `<img>`s use `crossOrigin="anonymous"` so cached responses are not opaque (quota padding).
- "Reload now" (`version/`) must fetch and activate the new service worker before reloading; a plain reload is still served from the old precache.
- Don't add a `beforeinstallprompt` handler that calls `prompt()` without a user gesture: it suppresses the browser's own install prompt and the call is rejected.
- The maskable icon is sized for the launcher showing about the central 88% of it (measured on a Pixel); the full-bleed size gets cut, the 80% safe zone looks small.
