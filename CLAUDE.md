# astroffers

PWA listing the NGC 2000 objects and the bodies of the Solar System visible on a given night at a given location. Vite, React 19, TypeScript (strict), MUI 9 (dark, emotion), Highcharts 13, sass; deployed as a Render static site ([render.yaml](render.yaml)) — **every push to `master` deploys** to https://astroffers.hasyee.com. Successor of the archived `hasyee/astroffers-electron` (desktop) and `hasyee/astroffers-app` (React Native) apps; tooling, the icons (`public/icons/`, copied onto this repo's file names) and the shared modules (`provider/`, `moon/`, `debounce/`, `version/version.hooks.ts`) came from `hasyee/astro-calendar` (MUI as well), which this app absorbed (its calendar is `calendar/`) and is archived now, not checked out — nothing to keep in sync. `location/` started from it but differs here (the coordinates are in the query).

## Structure

- Per-domain directories, flat file names: `src/<domain>/<domain>.<role>.ts(x)` (`.hooks.ts`, `.provider.tsx`, `.utils.ts`, `.types.ts`, `.scss`).
- State: the shareable state of the main view is in the URL query (`RouterProvider isQuerySticky`): `date=YYYY-MM-DD`, `lng`, `lat` always, every other param only when it differs from its default: `sort`, the search of the list (`ngc`, `messier`, `name`, left out when empty), the images of the table (`img=0` for the compact table, left out with the images, the default), the open calendar (`cal=1`, left out while closed), the red light mode (`red=1`, left out in the normal mode) and the filter (`alt`, `blt` — the brightness limit type, `mag` / `sb` —, `mag`, `sb`, `tw`, `ot`, `ow` — the observation window, `man` / `an` / `n` for the `moonlessNight` / `astroNight` / `night` of `NightInfo` (it replaced the moonless switch `ml`, and `blt` the `bf`; old links and stored filters are not migrated, nobody else uses the app); `const` and `types` list the selected keys, or the ones left out with a `-` before each when that is shorter, e.g. `const=-Aql,-Gem`, and are left out when everything is selected). Every param is a descriptor (`query/query.params.ts`, independent of the app: `createBoolParam`, `createNumParam` with a range, `createStringParam` with a pattern, `createEnumParam` by a list of the values or a map of them to their params, `createDateParam` as a `Date`; but the bool, each a list of its values with `{ isArray: true }`, comma separated — an enum list is a set (no duplicates, equal in any order), and relative to a non-null default it may be given by the values left out of it (`-` before each, the shorter form is written; a list mixing them is unknown); a `null` default allowed, a param with a non-null default is typed without `null`): its key, default and codec, a module constant in the utils of its domain (e.g. `CALENDAR_PARAM`), or a record of them by their names for a state of more params (`COORDS_PARAMS`, `SEARCH_PARAMS`, `FILTER_PARAMS` — a set of the filter is an enum list defaulting to all of its keys). The interface of the query state is hooks only (`query/query.hooks.ts`): `useQueryParam` / `useQueryParamSetter`, and `useQueryParams` / `useQueryParamsSetter` for a record (one selector, one update of the query for all of them — separate setters would recalculate with a half-updated state; the setter takes some of the values, or an update of all of them). The values keep their identity while other params change (selected by their strings — the param or the record must be a stable constant). A domain converts its values in its hooks (the filter by `toFilter` / `toFilterParamValues`; `useDate` the `Date` to the `Timestamp` used everywhere else). `readParam` / `writeParam` / `paramToQuery` are internal to `query/`. `query.params.ts` and `query.hooks.ts` stay independent of the app (to be reused by later apps; `QueryParam.isArray` and the lists of numbers, strings and dates are unused here but kept for them), the params of the app are in `query.utils.ts` / `query.storage.ts`.
  - `query/`: `restoreQuery` (`index.tsx`, before the first render, as the hooks read the query only) drops the params unknown to the app or having an unknown value (not in `STATE_PARAMS`, or their `parse` returns `undefined`: read as missing, not written back). A link (having a known state param, `hasKnownParam`) has its own state, a missing param is its default — that is what makes leaving them out shareable; a bare start (e.g. of the PWA, or a link of unknown params only) takes the stored params. The date (today without one) and the place (the stored one without one) are always written, the others only when they differ from their defaults. `useQueryStorage` (in `App`) stores the params but the date (`STORED_PARAMS`) in `localStorage` as a query string; the date is not stored (the night of today on every start). "Use my location" names the place `My location` (`MY_LOCATION_NAME`): while so, `useLocationFollowing` refreshes it on start, every minute and when the app gets visible, rounded to 0.01° (the jitter of the positioning would recalculate everything); typed coordinates, a searched place or a link to other coordinates rename it and stop the following.
  - `storage/`: `localStorage` has two items only, `query` (the stored params, a query string) and `locationName` (the name of the place of their coordinates; `restoreQuery` clears it for a link to another place); the items of other apps (e.g. on `localhost`) are left alone. The old items of the domains (`filter`, `sortBy`, ...) are not migrated.
  - The query is sticky: navigating without a query keeps it and back / forward change the path only, so closing a drawer or a dialog by the history never reverts a change made in it.
  - The rest are small `StateProvider`s on the hand-rolled context selector (`provider/context.selector.ts`, `useSyncExternalStore`): the name of the place (`LocationNameContext`, stored as `locationName`; its coordinates are params, changed by `useLocationSetter` only, with the name) and the result.
  - Every state has a value hook and a separate setter hook, never a `[value, setter]` pair: a component using only the setter does not rerender with the value (an update of the current value is read inside the setter, e.g. from the query by `useQueryParamSetter`, never from the value hook, which would make the setter depend on it).
- Routing: `router/` is tinc's router without its breadcrumb (`RouterLocation` / `usePathname` instead of `Location` / `useLocation`, not to clash with `location/`; added: `useNavigate({ replace })`, `useGoBack`, `useMatchPath`, the sticky query and `useQuerySelector` / `useQuerySetter`; `Routes`, `Route`, `Link` are there but unused — kept, as the app is a boilerplate of later apps too). The only route is `/:id` (the `id` of the object, e.g. `/m27`, `/ngc884`), the details over the main view (any other path of one segment, e.g. an old link, is not an object, so the details replace it with `/`): it stays mounted and reads `useMatchPath` (not `Routes`), so its closing is animated. Closing calls `useGoBack` (history back when opened in the app, else replace with `/`); stepping between objects replaces the route. The help and the about dialogs (opened from the footer of `sidebar/`, which frames the filter with its reset button — it resets the order and the search too — in the panel and the drawer) are state of `SidebarDialogProvider` above the layouts — the sidebar remounts when the layout changes (e.g. rotating a phone), which would close them —, without a route; like the filter drawer, they close with the back button by `useCloseOnBack` (`history/`: a history entry without a URL change, listing the keys of the open overlays, so back closes only the topmost one). `render.yaml` rewrites every path to `index.html`, the service worker's navigate fallback does the same offline.
- `result.hooks.ts` `useCalculation` reruns the calculation in a web worker (`calculator.worker.ts`) in two requests, matched by their own `jobId`s: the night at once on a change of the date, the place or the twilight (`useNight`, shown by the summary before the list arrives), then the list — at once for a new date, 300 ms after the last change otherwise (typed fields). The list's result keeps its own night and params (`useResultNightInfo`, `useResultParams`) for the details of its objects.
- The calendar (`calendar/`) is ported from astro-calendar and is the only date picker: the date button of the header toggles it (`useCalendarOpen`, in the query) above the summary, mounted only while open: on a wide screen a card of about half of the screen (`Collapse`); on a phone it fills the screen with the summary bar and the times of the night below it, instead of the list (no animation, the calendar takes the room left by the flex layout). The times of the night below the bar (a `Collapse`, no chevron; animated only when the bar alone toggles them, at once with the calendar, which has no animation) are local state of `CompactLayout`, three states: all closed → a click on the bar opens the times only, the date opens both; the times open → the bar closes them, the date opens the calendar too; both open → the date closes both, the bar does nothing. A click on a day sets the date, so the summary shows its night. It opens on the month of the chosen night (the month is local state), is swiped like the details (previous/current/next month), and has its own worker (`calculator.calendar.worker.ts`, month by month, the visible one first; one worker and cache for the whole session, per location and twilight, in `calendar.hooks.ts`, as the calendar is mounted only while open; `useCalendarPrefetch` calculates the month of the chosen night in the background a second after it changes, so the calendar opens with it at once; `calculator.bands.ts` from astro-calendar, but with the filter's twilight instead of a fixed -18°). The days are laid out by container queries on their cells (side by side in a wide cell, in a line above the Moon in a narrow one); its arrow keys work only when the focus is on the page or in the calendar, not in a field or an overlay.
- `calculator/` is the strict-ESM port of `astroffers-core` (the visibility of the objects). The Sun and the Moon are by `astronomy-engine` (`calculator.sun.ts`, `calculator.moon.ts`, helpers in `calculator.astronomy.ts`; it replaced `suncalc` and the NOAA approximation of the Sun): the sunset and the sunrise by the upper limb with the refraction (~6 minutes later / earlier than the center at 0° before), the twilight by the center. The night is searched from the solar noon of the longitude, not the noon of the device's time zone (night at a far location); compare altitudes geometric (no refraction, as the searches' -0.833°); search the next crossing a minute after the previous one (a search started at a crossing may return it). Checked against the old code over a year at 5 places (polar ones too): the differences are the refraction and the old approximations' errors. A calendar month takes ~23 ms on a desktop (~9 ms before).
- `catalog/catalog.json` is generated by `scripts/catalog.mjs` from astroffers-core's `data/` (radians, arc minutes, missing values omitted; 4 MB → 1 MB). Each object has an `id`: `m<Messier number>`, else `ngc<NGC number>`; a Messier number of two objects (M51: NGC 5194 and 5195, M76: NGC 650 and 651) is the id of the first one only. The source data gave M24 and M25 to NGC 4715 and 4725 (galaxies; they are IC 4715 and 4725): the script takes them off, and appends the Messier objects without an NGC number (M24, M25, M40, M45, from SEDS) at the end without `ngc` — `ngc` is optional, so sort, key and title by `id` / `getTitle`, not by `ngc`. Double stars (`**`, e.g. M40) are added to the filterable types. The core repo is archived and no longer checked out next to this one — pass its path as an argument.
- `solar/`: the planets, the dwarf planets and the brightest asteroids (opposition brighter than about magnitude 9; Massalia has no photo, Hygiea took its place) are objects of the list too (`NgcObject` without `ngc`, with a `photo` and a `skySource`), but they move: `calculator.ts` adds them for the middle of each night (`getSolarSystemObjects`, midnight for a polar night) with J2000 coordinates, so the precession and the visibility of the catalog work on them unchanged (their motion within a night is neglected). The planets and Pluto by `astronomy-engine` (geocentric, aberration on; magnitude, constellation — its symbols are ours), only in the worker (~136 KB); the other bodies by two-body Kepler orbits from the osculating elements of JPL's Small-Body Database (`solar.json`, by `scripts/solar.mjs`, one request at a time — the API answers 503 to parallel ones), light-time corrected, H-G magnitudes. Checked against JPL Horizons: arc seconds near the epoch of the elements, up to ~1° (Hygiea) six years away — rerun the script now and then. Their types (`Pl`, `DPl`, `MPl`; `Ast` is the asterism of the catalog) are in `solar.types.json`, merged into the types of the catalog in `catalog.utils.ts` (not regenerated with it). Photos: `<id>.preview.jpg` with the previews (see the UI conventions), 300px squares padded with black from the images of their Wikipedia articles (`sips`, which writes no WebP), kept only in the git-ignored `images/` and in the bucket; credits, licenses (some CC BY-SA) and Commons pages in `solar.photos.ts`, shown under the preview, linking to the page. Stellarium Web finds the planets by name, the minor bodies by their provisional designation only (`Iris` is a satellite, `Metis` a moon of Jupiter there).
- Responsive at 800px (`WIDE_SCREEN_QUERY` in `media/media.hooks.ts`): wide = Electron-like filter panel (open by default, the menu button of the header closes it; below 1110px, `FILTER_PANEL_QUERY`, it does not fit beside the summary, so the filter is in the drawer, closed by default) + table, narrow = React Native-like filter drawer, cards and a full-screen details carousel (`swipe/swipe.hooks.ts`, also used by the calendar: previous/current/next pages side by side, the track is reset in a layout effect after the step, so no blank page shows between them).

## UI conventions

- Theme in `theme/theme.ts` (dark: a black background and `#131313` papers, 7.5% white over the black, without the elevation overlay — the header (black on a phone, as the summary bar below it), the sidebar, the desktop summary, the dialogs, the menus, the header of the calendar (black on a phone too) and its weekends; the list, the summary bar of a phone, the calendar's days and the details page of a phone stay black, by the background color. The dividers are 18% white (none between the header, the summary bar and the toolbar of the cards on a phone: one black block); the floating papers (the dialogs, the menus, the filter drawer) have no outline; the stripes of the table are 4% white; the background is also the PWA's theme color, as a hex in `vite.config.ts` and `index.html`, 14px base font, small fields by default, 1rem dialog titles to fit the longer names of the objects — the compact details header matches it in `details.scss`; a custom `red` palette color, `augmentColor` of `red[500]` (`createTheme` computes the shades of the built-in colors only), whose dark shade (`var(--mui-palette-red-dark)`) is today in the calendar and the red light toggle; the font is Inter, bundled from `@fontsource-variable/inter` — the service worker precaches its latin subset only, the other subsets are cached at their first use) with `cssVariables: true`: the stylesheets use `var(--mui-palette-*)`, the charts read the palette through `chart/chart.colors.ts`. `StyledEngineProvider injectFirst` (`index.tsx`) puts MUI's styles first, so the SCSS overrides them at the same specificity. Styling stays in the per-domain `.scss` files, not `sx`.
- Import components and icons by path (`@mui/material/Button`, `@mui/icons-material/Close`); icon names are not guessable (the outlined help circle is `HelpOutlineOutlined`, `HelpOutline` doesn't exist), check `node_modules/@mui/icons-material`.
- Text buttons and `IconButton`s everywhere; fields are outlined `TextField`s with floating labels. Choices made in a dialog (Location, Selected types, Constellations) are read-only `SelectorField`s (`input/input.selector.tsx`). Dialogs use `DialogTitleWithClose` (`dialog/`), placeholders `EmptyState` (`empty/`).
- Red light mode (`redlight/`, the eye button of the header): two fixed layers over everything (`index.html` after the root, `index.scss`, shown by `html.red-light`, `pointer-events: none`): a `backdrop-filter: grayscale(1)` and a `rgb(179, 0, 0)` with `mix-blend-mode: multiply` map the brightness of every pixel to dim red (70%), so everything turns red without touching the components, the dialogs and drawers included. Tried and dropped: an SVG `feColorMatrix` filter on `<html>` (iOS ignores `url()` filters on the layers it composites apart — the scrolling list, the drawers stayed in color), and the same as a chain of CSS filter functions (`grayscale brightness sepia hue-rotate saturate`: exact in Chrome, but WebKit computes it in 8 bits a step, banded and non-monotonic). Playwright's headless WebKit applies no `backdrop-filter`, so check iOS on a device. Colors that differ in hue only (e.g. the bands of the night) differ in brightness only there, and a dark saturated color turns almost black (the eye button is red in the normal mode only, `html:not(.red-light)`).
- Preview images: DSS2 rendered by CDS hips2fits (on request, now and then up to half a minute) are re-rendered by `scripts/previews.mjs` into the git-ignored `images/` as grayscale JPEGs (mozjpeg q70, ~6 KB, ~45 MB in all; WebP came out larger on the star fields, AVIF saved little), uploaded with the photos of the Solar System by `aws s3 sync` (the command is in the README) to the `images/` of the `astroffers` S3 bucket (`eu-central-1`, private), served by CloudFront (OAC, its own CORS policy `astroffers-cors` allowing any request header — the managed `SimpleCORS` leaves `Access-Control-Allow-Origin` off for a request with a `Priority` header, which Chrome sends, so the `crossOrigin` images failed while `curl` looked fine; ACM certificate in `us-east-1`) at `https://images.astroffers.hasyee.com/images/<id>.preview.jpg` (`getObjectImgSrc`; distribution `EKV4Q4U9M9G15`; reachable through the AWS MCP or the local `aws` CLI), `Cache-Control: immutable` for a year — kept by CloudFront, the browsers and the service worker, so a changed image needs a new key (e.g. a new suffix in the code), an overwrite would not reach the users; out of the git history (they would grow it by every re-rendering); grayscale via CSS too (the photos are in color); the details preview opens nothing on a click (a 1200px color version did, but its slow loading after an accidental tap looked like a bug). The cards and the comfortable table (images toggled in the header of its first column, `useListImages`) show the same 300px image as the details. The square image of a card is as high as its text by fixed line heights (an SCSS sum in `list.scss`): a square stretched to the height of a flex row does not work in CSS (its width resolves to 0).
- The Open in menu between the previous / next buttons of the details (`external/`) opens the object on Wikipedia or, by a submenu (beside the item, above it on a phone, where there is no room beside), on Stellarium Web, now or at its best visibility. Wikipedia: `Messier <n>`, `NGC <n>`, or the `wikipedia` title of a body of the Solar System (`Mercury (planet)`, `4 Vesta`, ...) as `/wiki/` links, which the Wikipedia app takes over (verified app links; a missing article is an error page there); the NGC objects without an article (about half, listed by `scripts/wikipedia.mjs` in `external.wikipedia.json`) by `w/index.php?search=`, which the app does not take, so the browser lists the search results. Stellarium Web: `stellarium-web.org/skysource/<id upper-cased>?date&lat&lng&az&alt&fov` (the format of its own share link). The name lookup (`api.noctuasky.com/api/v1/skysources/name/<name>`) does not know every NGC object (e.g. NGC 6995), so the view is pointed by `az` / `alt` too (azimuth from north to east, as ours). The Stellarium Mobile / Plus apps have no documented deep link, and `stellarium-web.org` has no `assetlinks.json`, so the apps are not opened.
- Object types: the Object types select chooses all of them or a group (`objectTypeGroups` in `catalog/catalog.utils.ts`: Galaxies, Nebulae, Star clusters, Solar System; the few double stars of the catalog are in no group), the Selected types field below it (always shown) one by one in a dialog, listed by `typeOrder` (the groups side by side, the double stars after the star clusters). The select's value is derived from `types` only (`getTypeChoice`): Custom, disabled and shown only, when they make no group. A selectable Custom was dropped (2026-10-08): it needed a state of its own besides the query (to stay Custom when the types it chose made a group), with side effects.
- Hover styles go under `@media (hover: hover)`: on a touch screen a tapped element keeps `:hover`, which looked like a second selection in the calendar.
- Search: `*` in the Messier or name search matches every object having one, toggled by the asterisk button at the end of the field (`list/list.search.tsx`; typing it works too), so the Messier field has a plain numeric keypad on phones (`inputMode="numeric"`).

## Gotchas

- A selector of `useStateSelector` / `useQuerySelector` must return a primitive or an otherwise stable value: a new object on every call makes `useSyncExternalStore` loop. Select a string and parse it in a `useMemo` (`useQueryParam`, `useQueryParams`).
- Swipes (`swipe/swipe.hooks.ts`) call `preventDefault()` on the `touchmove`s of a horizontal swipe (non-passive listener): otherwise Chrome on Android starts a fling with nothing to scroll, and the next tap anywhere only stops it instead of clicking. Happens on a real device only, not in the emulator or headless.
- A `useEffect` callback must not return `element.scrollTo(...)`: it returns a Promise in current Chrome, React calls it as the cleanup, and the whole root unmounts. Use a block body.
- Highcharts polar: `pane.background: []` crashes (`innerRadius` of undefined) — pass an object; axis labels at the sides get ellipsized to nothing without a fixed `chart.margin` and `textOverflow: 'none'`; round `this.value` in label formatters (float ticks like 89.999). Highcharts 13 rounds the elements of a pane (`pane.borderRadius: 3`, e.g. the plot bands of the clock face): turned off in `chart.theme.ts`.
- `DialogTitle` + `DialogContent` zeroes the content's top padding, which clips the floating label of a first field — give that `DialogContent` a top padding (see `location.scss`). The `Autocomplete` of the place search ignores every `onInputChange` but typing (it resets the input itself on selecting) and uses `clearOnBlur={false}`.
- iOS zooms into inputs below 16px: `index.scss` sets 1rem only under `@supports (-webkit-touch-callout: none)` (iOS only; `!important` beats MUI's more specific selectors). The mobile tap highlight is turned off globally.
- The service worker caches the preview images (`runtimeCaching` CacheFirst in `vite.config.ts`; CloudFront sends them immutable for a year), and the `<img>`s use `crossOrigin="anonymous"` so cached responses are not opaque (quota padding).
- There is no version polling (unlike tinc, which has no service worker: here it only interfered with the service worker's own update). The About dialog checks `/version.txt` (written by the build, `npm run version`) when opened (by a unique URL: Render's CDN keeps every file for 5 minutes, `s-maxage=300`, so right after a deploy it answered the previous version) and offers an Update button; it (`useReloadToLatestVersion`, `version/`) must fetch and activate the new service worker before reloading, a plain reload is still served from the old precache.
- Don't add a `beforeinstallprompt` handler that calls `prompt()` without a user gesture: it suppresses the browser's own install prompt and the call is rejected.
- Portrait only on phones: `lockPhoneOrientation` (`media/media.utils.ts`, a screen shorter than 600px on its short side), not the manifest's `orientation`, which would lock tablets too. The browser allows the lock in an installed app only (Chrome on Android), not in a tab or on iOS.
- The maskable icon is sized for the launcher showing about the central 88% of it (measured on a Pixel); the full-bleed size gets cut, the 80% safe zone looks small.
- Checking the layout with Puppeteer: `setViewport` with a changed `isMobile` reloads the page, and a screenshot beyond the viewport resizes it — both close the open dialogs / drawers and switch the layout, which is not a bug of the app. The swipe tracks keep the previous and next pages beside the current one (on a wide screen the previous month of the calendar lies under the sidebar): click an item of the visible page, by its position.
- `prettier --write src` reformats the generated `external/external.wikipedia.json` too: format the changed files only (`npx prettier --check src` warns about it, which is expected).
